# Four-Player Quiz Buzzer on FPGA (Nexys 4 DDR / Nexys A7)

A four-player quiz buzzer built in **Verilog** on the **Digilent Nexys 4 DDR (Nexys A7-100T)** using **AMD Vivado**. The first player to press wins: their LED lights, the 7-segment display shows their number, a buzzer sounds for half a second, and every other player is locked out until the reset button is pressed.

## The story: why an FPGA

We started with discrete ICs. It took **three trips to the electronics shop**, 20 ICs bought and only 10 used, and over **60 jumper wires** across two breadboards. The wiring became impossible to trace, and the reset button ended up buried under it. After an all-nighter the circuit still didn't work reliably, so we moved the whole design to an FPGA, where the same logic is a few lines of Verilog.

## Features

- Four players, each with a push button and an LED
- First-press detection with lockout of all other players
- Common buzzer, 1 kHz tone for 0.5 s on each win
- Single-digit 7-segment display showing the winning player's number
- Reset button (debounced) to start the next round
- Timing met in Vivado with no failing paths

## How it works

![Block diagram](docs/block-diagram.png)
<!-- Add a simple block diagram: buttons > synchronizer > edge detector > winner latch > LEDs / display / buzzer -->

1. **Synchronizer.** Each button passes through two flip-flops to avoid metastability.
2. **Edge detector.** A one-cycle pulse is created on the rising edge, so a held button counts as one press.
3. **Winner latch and lockout.** If no winner is set, the first press sets one bit for that player. Once set, all later presses are ignored. If two presses land in the same clock cycle, the lowest player number wins.
4. **Buzzer.** A 0.5 s counter gates a 1 kHz tone generated by a clock divider on the 100 MHz clock.
5. **Reset.** The reset button is synchronized and debounced for 20 ms, then clears the winner.
6. **Display.** The one-hot winner flags are decoded to a segment pattern. The board's display is common-anode, so segments and enables are active low.

Player buttons are **not** debounced on purpose: a delay could differ between buttons, and bounce after the first edge is harmless because the system is already locked.

## Wiring

![Wiring photo](docs/wiring.jpg)
<!-- Photo or diagram of the buttons, LEDs and buzzer connected to the Pmod headers -->

- **Buttons:** all four share one 3V3 connection from a Pmod pin. Each button goes between 3V3 and its JB pin, using diagonally opposite legs of the 4-leg button. The FPGA's internal pull-down holds the pin low when the button is released.
- **LEDs:** each JC pin goes through a 330 ohm resistor to the LED's long leg, and the short leg goes to a Pmod GND pin.
- **Buzzer module:** VCC to 3V3, GND to GND, I/O to JA1.
- The Nexys A7 I/O is 3.3 V only. Never connect 5 V to a Pmod pin.

## How to build and run

1. Open Vivado and create a new **RTL project**.
2. Choose the part `xc7a100tcsg324-1`.
3. Add `quiz_top.v`, `quiz_buzzer.v` and `seg_display.v` as design sources, and `quiz_top.xdc` as the constraints file.
4. Set **`quiz_top`** as the top module.
5. Click **Generate Bitstream** (this runs synthesis and implementation).
6. Connect the board with the micro-USB cable and power it on.
7. In **Hardware Manager**, click **Open Target > Auto Connect**, then **Program Device**.
8. The green DONE LED lights when programming succeeds.

If your buzzer module is high-level-trigger instead of low-level-trigger, set `IDLE_HIGH = 0` in `quiz_buzzer.v`.

## What we learned

- The full Vivado flow: synthesis, implementation, bitstream and programming.
- Mapping ports to pins with constraints, and that a change means rebuilding and reprogramming.
- Synchronizers, edge detection and when debouncing is and isn't appropriate.
- Debugging on real hardware by testing one piece at a time: a jumper wire in place of a button, on-board LEDs in place of external ones, and a multimeter on the 3V3 rail.
- Sometimes the right fix is to change the tool rather than push harder on the wrong one.
